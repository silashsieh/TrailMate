# TrailMate v2.0.0 — Design & Implementation Plan

**Scope:** Three scheduled epics — 012 (simultaneous multi-device), 019 (AI command integration), 021 (menu bar + background). All major decisions are already settled; this document merges them into one dependency-ordered build plan and a concrete multi-agent orchestration strategy.

**Repo:** `/Users/harry/Documents/pikmin/TrailMate` · Swift sources under `TrailMate/*.swift` · daemon under `PythonDaemon/` · epics under `docs/project-plan/epics/`.

## 1. Executive summary

v2.0.0 turns TrailMate from a single-device GPS simulator into a multi-device, AI-drivable, background-capable app:

- **012 — Multi-device:** Connect and drive N paired iPhones at once. Shared map shows N color-coded markers + routes; a sidebar device *switcher* selects which device the single control surface (planner, playback bar, joystick) drives.
- **019 — AI integration:** An in-app Unix-domain-socket command server (line protocol, off by default) lets `trailmate` CLI / Claude Code drive the app through the *same* API the GUI uses.
- **021 — Menu bar + background:** A `MenuBarExtra` with live status + quick actions; closing the main window keeps the simulation and AI socket alive; the Dock icon appears/disappears dynamically.

**The one load-bearing refactor everything depends on:** carving the single-device `AppState` god-object (`AppState.swift`, ~1074 lines) into a **UDID-keyed `DeviceManager`** (`@MainActor @Observable`, app-global concerns) owning **N `DeviceSession`** (per-UDID connection + sim + route state). The D7 actor split already did the hard isolation work — each `DeviceSession` is a clean replica of what `AppState` owns today (one `SimulationActor` + one `SimulationStateBridge` + one `DaemonBridge` + connection/route/playback state). **Nothing in 019 or 021 can land in its final form until this "sessionize" step exists**, because both dispatch through `DeviceManager`/`DeviceSession`:

- 019's command server calls `DeviceManager.dispatch(udid:command:)` — the same facade the GUI uses.
- 021's quit handshake fans out over `DeviceManager.sessions`; its menu rows iterate them.

**The structural invariant that makes multi-device correct (the top risk, made structural not runtime):** device identity is UDID-keyed end-to-end — *command → session → daemon → tunnel*. Each `DeviceSession` holds its `DaemonBridge` **private**; `DeviceManager` exposes `teleport(udid:…)`-style facade methods that resolve `sessions[udid]` and forward. No session ever references another's bridge, and a `SimulationActor` only ever talks to the backend injected at its own `attach(backend:)`. "A's coordinate reaches B's daemon" is therefore impossible by construction. `tm_daemon.py`'s line protocol is **unchanged** — device identity is structural (each daemon is bound to one RSD addr/port).

Beyond the actor replication, only **four shared sinks/globals** are real refactor work (the actors already isolate cleanly): (1) `SimulationStateBridge` → per-session; (2) `RecorderService` → split capture (per-session) / library (app-wide); (3) `SimulatedPositionPersistence` → UDID-keyed; (4) `GCController`/joystick → single observer owner on `DeviceManager`, input bound to the selected session only. The tunnel stays **one broker, one sudo prompt, N tunnels** via the `pymobiledevice3 remote tunneld` hybrid — gated on a verification spike.

## 4. Multi-agent orchestration strategy (ultracode)

The naive plan ("three agents, one per epic, in parallel worktrees") is **wrong-shaped** because the branches are *not file-disjoint*. The load-bearing analysis is cross-referencing the three epics' `fileChanges` to find files touched by more than one branch. Those files are the serialization constraints.

### File-overlap map (the constraint that drives staging)

| File | Touched by | Verdict |
|------|-----------|---------|
| **`TrailMateApp.swift`** | 012 step 1 (`@State AppState`→`DeviceManager`), 012 step 5 (quit fan-out: save-all + disconnect-all), 019 step 4 (quit-time socket unlink), 021 step 6 (scene graph: `Window(id:)`, `applicationShouldTerminateAfterLastWindowClosed=false`, activation policy) | **WORST conflict point — 4 edits across 3 epics. Single-owner or serial integration only.** |
| **`SettingsView.swift`** | 019 step 4 (AI-control section), 021 step 11 (menu-bar + Dock sections) | 2 branches — append-only sections; low conflict but coordinate. |
| **`DeviceManager.swift`** (new, from step 1) | 012 step 5 (broker wiring), 019 step 3 (`dispatch`), 012 step 8 | Owned by sessionize; later branches *add methods*. Serialize the additions or single-own. |
| **`ContentView.swift`** (~1716 lines) | 012 step 8 only | Clean — single branch owns it. |
| **`SimulationActor.swift`** | 012 step 1 (hoist GCController, App Nap consolidation) | Step 1 only; frozen afterward (021's App Nap story is *verify-only, no edit*). |
| **`tm_tunnel.sh`**, **`TunnelBroker.swift`** | 012 step 5 only | Clean — broker branch owns. |
| New files: `CommandServer/CommandProtocol/SocketPath.swift`, `MenuBarStatusView.swift`, `CLI/…` | one branch each | **Fully parallel — zero conflict.** |

**Conclusion:** parallel agents own their *new files* freely. The *shared hot-spot files* (`TrailMateApp.swift` above all, then `SettingsView.swift`, `DeviceManager.swift`) need either a single owner or a serial integration pass. `TrailMateApp.swift` is only ~47 lines but is rewritten by three branches — it is the merge bomb.

### Stage shape

**Stage A — SERIAL GATE (1 agent, on `main` or a single worktree).**
One agent does **step 1 (sessionize + RoutingService)** as one coherent refactor. Do **not** split it across agents — sessionize is a single conceptual cut; splitting invites incoherence. This rewrites `AppState.swift` (→ `DeviceManager`/`DeviceSession`), `TrailMateApp.swift`, `SimulationActor.swift`, `SimulationBackend.swift`, `RecorderService.swift`, `SimulatedPositionPersistence.swift`, `ContentView.swift` (mechanical rebind to facade), `SettingsView.swift` (rebind to `DeviceManager` globals), plus new `RoutingService.swift` / `MapKitRoutingService.swift`. **Concurrent 0th track:** a research/spike agent runs step 0 (tunneld spike) in parallel — it touches no Swift app code (`PythonDaemon/` + a scratch shell), so it cannot conflict. The spike result must land before Stage B's broker agent starts.

**Stage B — PARALLEL IN ISOLATED WORKTREES (3 agents + 1 follow-on).** All branch off the post-sessionize tree.

| Agent | Owns (files) | Steps | Conflict surface |
|-------|--------------|-------|------------------|
| **B1 — Tunnel broker** | `TunnelBroker.swift` (new, ex-`TunnelSupervisor`), `tm_tunnel.sh`, broker wiring in `DeviceManager.swift` | 5 | `DeviceManager.swift` (add methods) |
| **B2 — AI command server + CLI** | `CommandServer.swift`, `CommandProtocol.swift`, `SocketPath.swift` (all new), `CLI/…` (new target), `dispatch()` in `DeviceManager.swift`, AI section in `SettingsView.swift` | 2,3,4,12 | `DeviceManager.swift`, `SettingsView.swift`, `TrailMateApp.swift` (quit unlink) |
| **B3 — Menu bar + lifecycle** | `MenuBarStatusView.swift` (new), scene graph + activation policy in `TrailMateApp.swift`, menu/Dock sections in `SettingsView.swift` | 6,7,9,10,11 | `TrailMateApp.swift`, `SettingsView.swift` |
| **B4 — Switcher UI** (starts when B1/step 5 lands) | `ContentView.swift`, log-tagging in `DeviceManager.swift` | 8 | `ContentView.swift` (sole owner — clean) |

**`TrailMateApp.swift` resolution (the must-state rule):** three branches want it (B2 quit-unlink, B3 scene graph, 012-step5 quit fan-out). **Designate B3 (menu/lifecycle) as the single owner of `TrailMateApp.swift`.** B2 and B1 do NOT edit it in their worktrees; instead they expose the hooks they need (`CommandServer.stop()`, `DeviceManager.disconnectAll()`) and hand B3 a one-line integration note. B3 wires all three concerns (`applicationShouldTerminate` fan-out + socket unlink + activation policy) in one coherent pass. This collapses the worst merge point to a single author.

**`SettingsView.swift`:** both B2 and B3 append a `Section` to the same `Form`. Low risk (append-only), but to be safe, **B3 owns `SettingsView.swift`** and B2 hands it the AI-control `Section` as a self-contained subview (`AISettingsSection`) to drop in — so B2 ships a *new file* and B3 inserts one line.

**`DeviceManager.swift`:** owned by Stage A. B1, B2, B4 each *add methods* (broker calls, `dispatch`, log-tagging). These rarely collide (different methods), but to be deterministic, integrate them in order B1 → B2 → B4 at merge time, or have each add its methods in a clearly-delimited `// MARK:` block.

**Stage C — ADVERSARIAL REVIEW + ON-DEVICE VERIFY (gate, 2 agents).**
- **code-review agent** (`/code-review` at high effort): focus on the device-routing invariant (no cross-session `DaemonBridge` reference; `dispatch` never reads `selectedDeviceUDID`), N-actor isolation, and the `emit()` chokepoint (every AI/GUI coordinate still passes noise+recording).
- **verify agent** (`/verify` skill, on-device smoke): the proofs the source can't give — two phones moving independently; teleport device A doesn't move B; close window → device keeps moving (App Nap); sleep/wake tunnel recovery with no new prompt; `trailmate teleport <udid>` moves only that device.

These run after each Stage-B branch merges and again on the integrated tree (steps 13/14).

### Realistic agent count per stage

- **Stage A:** **1** refactor agent + **1** concurrent spike agent = 2.
- **Stage B:** **3** parallel (B1 broker, B2 AI, B3 menu) + **1** follow-on (B4 switcher, unblocks when step 5 lands) = up to 4.
- **Stage C:** **2** (review + verify), repeated as a gate per merge.

**Merge-conflict minimization order:** land **B3 (TrailMateApp owner)** into the integration branch *last among the hot-spot writers* so it integrates the final shape of `applicationShouldTerminate` against the already-merged broker (B1) and AI (B2) hooks. Land **B4 (ContentView)** independently any time after step 5 — it touches no shared file. The spike (step 0) and pure-value-type step 2 carry zero conflict risk and can land whenever.

## 5. Risk register

| Risk | Severity | Mitigation |
|------|----------|-----------|
| **Device-routing correctness** — a command for device A reaches A's daemon, never B's. With N sessions a mis-wired backend silently spoofs the wrong phone with no error. | **Top** | Structural: `DaemonBridge` is **private** to its `DeviceSession`; backend injected only at that session's own `attach()`; `DeviceManager` facade + `dispatch()` resolve `sessions[udid]` and forward; `dispatch` **must never read `selectedDeviceUDID`** (GUI/joystick state only). Enforce in code-review; `CommandDispatchTests` with ≥2 mock sessions proves A-never-moves-B. |
| **Tunnel-broker spike (BLOCKING prerequisite)** — `remote tunneld` sleep/wake recovery without a new sudo prompt on macOS 26.4 / iOS 26.4 is source-plausible but unverified (pmd3 has a documented macOS socket-fragility class on other OS versions). | **Top** | **Step 0 spike gates step 5.** Run it concurrent with sessionize. Decisive test: sleep→wake→`GET /` recovers tunnels with no auth dialog. **Fallback:** generalize `tm_tunnel.sh` to manage N `lockdown start-tunnel` sessions under one root process (inferior — no hot-plug, re-spawn risks re-prompt), kept behind the same `TunnelBroker` two-method interface so callers don't change. Do NOT assert recovery as fact in the epic until verified. |
| **N-actor races** — N `SimulationActor`s sharing one `SimulationStateBridge` → last-writer-wins corruption of markers/progress/recording. | High | Per-session `SimulationStateBridge` (constructed in `DeviceSession.init`). Independent actors, no shared mutable state — idiomatic Swift 6; cross-actor traffic is already `Sendable` value types + the existing `Task { @MainActor in bridge.apply(snap) }` hop. The map fans over N bridges. |
| **One physical joystick, N engines** — `GCController` observers live inside the per-session actor; naive replication arms every device from one controller. | High | Hoist `GCController` observation out of `SimulationActor` to `DeviceManager` (single owner); joystick input + controller-name display bind to the **selected** session only; on switch, `stopJoystick` old + `startJoystick` new. `JoystickEngine.tick()`'s global controller read stays harmless because non-selected engines have `isActive==false`. |
| **Merge conflicts in `TrailMateApp.swift`** — 4 edits across 3 epics on a ~47-line file. | High | Single-owner (B3 menu/lifecycle agent) integrates all three concerns; B1/B2 expose hooks (`disconnectAll()`, `CommandServer.stop()`), don't edit the file. `SettingsView.swift` similarly single-owned with B2 handing over a self-contained `Section` subview. |
| **App Nap throttling the windowless 20Hz loop** | Medium | **Already covered** — `activityToken` is connection-scoped (held `attach`→`detach`), a superset of simulation lifetime; the app-lifetime root `@State` survives window close, so `sim` + token survive. **Do NOT relocate the token** (would re-introduce window-coupling). Step 10 = empirical verify + document, no edit. |
| **MapKit per-Mac routing throttle under N** — N devices planning at once = N×legs contending on one global budget. | Medium | `RoutingService` is a **stateless, app-level shared service** on `DeviceManager` (per-session buys nothing — the throttle is per-process). Route *output* is per-session. Self-hosted OSRM is the deferred mitigation (012 step 1 / D4); `MapKitRoutingService` stays default. Keep legs sequential. |
| **Stale-daemon sweep is all-or-nothing** (`pkill -f tm_daemon.py`) | Medium | Use only as a **cold-start orphan cleanup** before the first connect (on `DeviceManager`). Per-device reconnect terminates only that session's specific `Process` (DaemonBridge already does), never the global `pkill`. |
| **Unreachable-app trap (021)** — hide menu-bar item while `.accessory` with no window → no Dock icon AND no menu item → invisible, unquittable. | Medium | Couple "hide menu bar item" with forcing a Dock icon, or disallow hiding while windowless. Bake into the Settings story (step 11). |
| **Stale AF_UNIX socket** — `SO_REUSEADDR` is a no-op for `AF_UNIX`; a crash leaves the file → next `bind()` fails `EADDRINUSE`. | Low | `unlink()` before `bind()` on launch (mandatory), and on toggle-off/quit. Single-user/single-instance — no lockfile dance. Assert `sun_path < 104` bytes. |
| **`SMAppService.mainApp` free-Apple-ID-safe unverified** | Low | Optional story (15); validate on the real ad-hoc build, register only from `/Applications` (path-pinned; guard the worktree-symlink trap). Contained — optional. |
