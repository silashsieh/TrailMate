## 1. Executive summary

TrailMate idles at ~12% CPU visible and reads 15–30% during route playback. Three causes, one
root, all in the presentation layer (the simulation loop is already negligible after 034/035):

1. **SwiftUI `Map` never sleeps.** The two-way `position:` binding keeps VectorKit repainting
   whenever the window is visible (DTS thread 705203; Apple Maps' raw `MKMapView` idles ~0%
   on the same renderer).
2. **Playback re-evaluates the whole map content at 2 Hz.** The `Map` content builder reads
   `simulatedCoordinate`, so every snapshot re-declares every session's `MapPolyline` and all
   markers. The 2 Hz throttle in `SimulationActor` exists only to bound this.
3. **Follow mode animates the camera every 500 ms** (`withAnimation { cameraPosition = … }`),
   keeping the map in permanent animation — the ~30% end.

**The fix (two epics, one integration):**

- **041 — telemetry plane:** `SimulationActor` publishes a latest-wins
  `AsyncStream<TelemetryFrame>` (coordinate, progress, elapsed, deviation, recording count);
  structural state keeps flowing through the `@Observable` bridge but with per-field change
  guards (Observation doesn't dedupe same-value writes). `DeviceSession` gains `routeVersion`.
  Additive; zero visible change.
- **037 — map surface:** `MapSurface` (`NSViewRepresentable`) hosting one `MKMapView`, driven
  imperatively by a `MapSurfaceController` coordinator: overlays diffed by
  `(sessionID, routeVersion)`, per-session dot annotations moved **in place** from the
  telemetry stream, camera via `setRegion`/`setCenter(_:animated:)`, follow-disengage via
  gesture recognizers. Deletes the `position:` binding, both `.onMapCameraChange` handlers,
  and the follow `onChange` hack. Then playback telemetry rises to 10 Hz (smoother dot,
  lower CPU).

**Load-bearing property:** a coordinate-only tick never re-evaluates map content (no
`MapSurface` update pass, no overlay reconciliation) — the dot moves by in-place annotation
mutation. Small isolated SwiftUI readouts (progress, recording count) keep updating throttled
and equality-guarded; SwiftUI re-renders structurally only on real change.

**Stream discipline (WP6):** each per-session telemetry `AsyncStream` is single-consumer — the
integration layer is the sole iterator and fans out internally (dot + camera). Never attach two
iterators to one stream; cancel consumer tasks by session ID / surface lifetime.

**Targets (window visible — occluded windows pause MapKit and read a false ~0%):**
idle+route ≈ 1% (from ~12%); playback low single digits, Follow no longer a distinct tier
(from 15–30%); no `AttributeGraph: cycle detected`; all map features behave identically.

## 2. Frozen contracts (agents build against these, not against each other)

Names and responsibilities are frozen so work packages can proceed independently; internals
are the implementing agent's latitude. All new types follow repo conventions (one type per
file, `@Observable` over ObservableObject, strict concurrency).

```swift
// TelemetryFrame.swift (041) — Sendable value type
struct TelemetryFrame: Sendable {
    var coordinate: CLLocationCoordinate2D?   // last emitted clean position
    var progress: Double                      // 0…1 within the current leg
    var elapsedDistance: Double               // meters along route
    var routeDeviationMeters: Double
    var recordingPointCount: Int
}

// SimulationActor (041) — one stream per actor, latest-wins
var telemetry: AsyncStream<TelemetryFrame>    // AsyncStream(bufferingPolicy: .bufferingNewest(1))
// Structural fields keep flowing via SimulationStateBridge, but every bridge
// property write is change-guarded (write only if the value actually differs).

// DeviceSession (041)
private(set) var routeVersion: Int            // bumped in routeCoordinates.didSet

// MapSurface.swift (037) — the representable; body inputs are STRUCTURAL only
struct MapSurface: NSViewRepresentable {
    var model: MapSurfaceModel                // sessions (id/color/isSelected/routeVersion/route),
                                              // markers, stroke, isDrawingRoute, focus, isFollowing
    var handlers: MapSurfaceHandlers          // onLongPressCoordinate, onUserCameraGesture,
                                              // onCameraIdle(region), onStrokeChanged, …
}

// MapSurfaceController.swift (037) — MainActor NSObject coordinator, MKMapViewDelegate.
// Owns the MKMapView and four collaborators (each its own file):
//   MapOverlayStore.swift     — MKPolyline per session keyed by (sessionID, routeVersion);
//                               stroke polyline; start/stop/end/destination markers
//   MapAnnotationStore.swift  — one stable dot annotation per session; coordinate mutated
//                               in place from the telemetry stream; never rebuilt as an array
//   MapCameraDirector.swift   — persisted region, follow + follow-span via
//                               setCenter(_:animated:), focus-on-saved-item; follow-disengage
//                               keys off regionWillChangeAnimated WITH a programmatic-change
//                               guard (AppKit has no positionedByUser equivalent)
//   MapGestureBridge.swift    — right-click (NSClickGestureRecognizer buttonMask 0x2 → NSMenu),
//                               long-press (NSPressGestureRecognizer 0.5 s), freehand draw
//                               (NSPanGestureRecognizer, draw-mode only, isScrollEnabled=false
//                               while drawing, isZoomEnabled stays true). Points captured in
//                               AppKit recognizers (location(in:)) — never SwiftUI (y-flip
//                               trap); no hover tracker. Full arbitration: epic 037 Decisions
//                               + docs/project-plan/spikes/037-gesture-spike-findings.md
// Telemetry subscription: injected as (DeviceSession.ID) -> AsyncStream<TelemetryFrame>,
// so the controller never imports AppState.
```

Contract rules:
- `MapSurfaceModel` carries **no per-tick data**. If a value changes at telemetry rate, it
  travels on the stream, not the model.
- `updateNSView` diffing is O(sessions): compare `routeVersion` ints and selection, never
  coordinate arrays.
- The joystick inset, top overlay chips, and destination action bar remain SwiftUI, layered
  over `MapSurface` exactly as they layer over `Map` today — out of the controller's scope.

### Merge mechanics (repo conventions)

- One worktree per WP: `../TrailMate-epic-<NNN><letter>`, branch `feat/<NNN>-<slug>`;
  **symlink `PythonResources` from the main checkout into each worktree** or the build fails
  (`CpResource … couldn't be opened`).
- Merge order: WP1 → (WP3, WP4, WP5 in any order — disjoint new files) → WP6.
  WP2 is never merged (spike); its findings land as text in 037.
- Build-gate each branch locally (`xcodebuild … build` + tests); squash-merge; Conventional
  Commits (`perf:`/`feat:`/`refactor:`); do **not** launch the built app if Harry's live
  `/Applications` session is running (`pgrep -lf TrailMate` first).
