# Risks & Mitigations

Ongoing risks for the current product. Update when a mitigation changes or a new risk surfaces.

|Risk                                                  |Likelihood|Impact                                   |Mitigation                                                                                                                                  |
|------------------------------------------------------|----------|-----------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
|iOS major-version DDI / RSD upload instability        |Medium    |Connect fails until the DDI is re-mounted|We do not auto-mount; surface a "please mount via Xcode first" UX. Toggling Developer Mode off and on often clears stuck state.             |
|pymobiledevice3 API breaking change in a minor version|Medium    |Daemon stops working                     |Pin to a known-good version (see [tech-stack.md](../technical/tech-stack.md)). Bump deliberately and run a smoke pass.                      |
|Apple changes the RSD protocol in a future iOS        |Medium    |Breaks everything                        |Inevitable. Monitor pymobiledevice3 releases. We're not unique — every spoofer breaks here.                                                 |
|`osascript` admin prompt UX is jarring                |Medium    |Annoying                                 |Accepted: one prompt per session. A packaged SMAppService helper remains separate deferred work (see features.md).                         |
|Tunnel drops mid-session                              |Medium    |Bad UX                                   |Tunnel-down / daemon-exit callbacks tear down the affected backend and surface the reason; an armed session makes up to 10 promptless recovery attempts. Another device and the local route/recording keep running.|
|Wi-Fi tunnel drops more often than USB                |Medium    |iPhone reverts to real GPS until recovery|The same per-session loss path and promptless retry policy apply to Wi-Fi. A failed or unarmed session can be reconnected manually.|
|`isSimulatedBySoftware == true` visible to apps       |Certain   |Some apps detect the spoof               |Documented limitation. Not a goal to defeat.                                                                                                |
|Game-controller incompatibility                       |Low       |Joystick unusable for some controllers   |On-screen virtual stick and WASD / arrow-key input are always available as fallback.                                                        |
|Bundled Python runtime breaks on a macOS upgrade      |Low       |App won't launch after OS update         |python-build-standalone is well-maintained; smoke-test on each macOS major before tagging a release.                                        |
|pymobiledevice3 license obligations (e.g. LGPL/GPL)   |Low       |Legal                                    |Verify the bundled pymobiledevice3 license is compatible with TrailMate's MIT before publishing a release. Re-verify on dep bumps.          |
|Developer ID or notary credentials leak/expire       |Low       |Release compromise or failed publishing |Keep private material in the protected GitHub `release` environment, use an ephemeral runner keychain, never upload it as an artifact/cache, and rotate/revoke credentials immediately if exposed.|
|Nested Python code or bundle metadata is damaged during packaging|Medium|Gatekeeper/notarization rejects the app, or a notarized DMG contains an invalid app|Sign every embedded executable and library with the host identity and Hardened Runtime, stage with metadata-preserving `ditto`, then deep-verify the exported app, staged app, and exact app mounted from the finished DMG before publishing.|
|Sparkle signing key leaks or is lost                  |Low       |Malicious updates, or no upgrade path    |Keep the private key in the protected `release` environment with a mode-`600` offline recovery export; ship only the public key, never log/cache/artifact the secret, and rotate via an explicitly planned transition if compromised.|
|Appcast advertises an unavailable release asset      |Low       |In-app update fails                      |Upload into a draft release, publish it only after all assets succeed, and deploy the signed appcast to Pages last. Manual DMG installation remains the recovery path.|
