# v2.2.0 idle-CPU work — baseline measurements & feature-parity checklist (WP0)

> Companion to [[v2.2.0-design]]. Fill the baseline table BEFORE the map migration lands;
> WP7 verification re-runs the identical protocol after and compares. Owner: Harry (the
> window must be visibly on screen — agents cannot measure this).

## Measurement protocol

- **Build:** profile the same configuration before and after (recommend a local Release
  build; a Debug build is acceptable if both sides use Debug). Note which one below.
- **Record the exact commit SHA** (`git rev-parse HEAD`) with every run — version text cannot
  identify the binary: the installed `/Applications` v2.1.0 (tag `544605a`) predates the
  034/035 CPU fixes (`632bfb7`, `959ceb6`) yet reports the same "2.1.0 (8)". **Do not baseline
  the installed app** — build from current `main` so before/after differ only by the map work.
- Note route size (vertex count), session count, and map style alongside region/zoom.
- **Window fully visible, frontmost, un-occluded.** An occluded or background-launched
  window pauses MapKit rendering and reads a false ~0% — those numbers are invalid.
- **Machine otherwise idle;** same map region/zoom and the same saved route for every run.
- Per scenario: let it settle ~10 s, then sample **~60 s**. Record Activity Monitor's
  average %CPU for TrailMate, and (for scenarios 1–2 at minimum) a Time Profiler trace —
  note whether `md::MapEngine::render` / `ggl::MetalRenderItem` dominate.
- Also note any `AttributeGraph: cycle detected` spam in Console.app during the run.

## Release A/B results (2026-07-11) and cadence decision

Three Release variants of the integration build, 20 s visible-window `ps` averages, same
route, binary-path-verified per run (full data: `../../../abtest/README.md`):

| Scenario | A: 10 Hz control | B: flat elevation | C: 5 Hz telemetry |
|---|---|---|---|
| s2 idle + route | 8.9% | 9.9% | 10.6% |
| s3 playback, Follow off | 21.1% | 23.2% | **14.8%** |
| s4 playback, Follow on | 22.4% | 24.2% | **13.6%** |

Validity note: the A/B table above was measured at the pre-review-fix head and is the
DECISION basis for the 5 Hz cap. The shipped build's certified numbers are the final-head
revalidation (2026-07-13, RC2 = review-fixed head, same route/protocol, normal zoomed
window): **s2 idle+route 0.5% · s3 playback Follow-off 7.4% · s4 Follow-on 8.4% · s5
joystick 5.8%** (s5 is an interaction sample — repeated virtual-stick drags with CPU spikes
aligned to active input — not continuous held-input telemetry). All pass-bands met; the
pre-existing ~9% idle-with-route floor did not appear in this run. The terminal-publication
fix was also verified live: a 100× playback to completion returned the UI to idle with the
position at the exact route endpoint.

Verdict: render-pass **frequency** (dot moves per second) caused the playback regression —
terrain redraw was exonerated (B ≈ A within the ±2 pt noise band; `.realistic` stays). The
5 Hz cap ships as `SimulationTiming.mapTelemetryInterval` (200 ms); it beats every
pre-migration figure (Follow-off 15%, Follow-on 30% on `de873e2`) while keeping the dot 2.5×
smoother than the old 2 Hz. The ~9% idle-with-route floor is pre-existing (equal on the
before build) and is follow-up work, not part of this change.

## Feature-parity checklist (walk through after WP6 integration)

Map content
- [ ] Per-session simulated dot, session-palette color, selected session emphasized
      (16 pt + 3 pt white ring vs 12 pt + 2 pt); dots for ALL sessions simultaneously.
- [ ] Route polylines per session: selected 4 pt / full opacity, others 3 pt / 0.7.
- [ ] Hand-drawn stroke: orange dashed (6/4), round caps, 3 pt.
- [ ] Markers: Start (green flag.fill), numbered Stops (blue N.circle.fill), End (orange
      mappin), Destination (purple mappin.and.ellipse).

Camera
- [ ] Region persists across relaunch (same center/zoom).
- [ ] Follow: engages on button, tracks the dot without changing user-chosen zoom
      (follow-span), disengages on any user pan/zoom gesture, disengages when location
      is cleared.
- [ ] Focus-on-saved-item frames the location/route; picking the same item twice refocuses;
      focus disengages follow.

Interactions
- [ ] Right-click anywhere → context menu; chosen action uses the coordinate under the
      pointer at click time.
- [ ] Long-press (~0.5 s): first-ever press teleports; with an existing position it shows
      the destination action bar.
- [x] Draw mode: drag draws the stroke; map pan suppressed but zoom (scroll/pinch) live;
      *(PASSED 2026-07-12 on RC1: Fujian→Taiwan drag → ~380.6 km route loaded, Play +
      Export GPX enabled — the final manual gate.)*
      pointer style changes; pan restored on exit. **Accepted deviation:** Esc does NOT
      exit draw mode (MKMapView first-responder swallows the key before SwiftUI's
      .onKeyPress); the pencil button is the exit — owner decision 2026-07-12.
- [ ] Destination action bar: Teleport / Go directly / Route here / Wander / Append
      (direct + route) / Copy (bar stays up after Copy).
- [ ] Joystick inset: MapKit compass/zoom controls reflow above it when active; WASD/arrow
      keys steer while joystick is active.
- [ ] Playback scrubber seeks during playback; dot follows.

Post-integration additions (from the WP4/WP6 review fixes — same walkthrough)
- [ ] **Window close → reopen: dots resume moving** (renewable telemetry stream; the old
      stored-stream design froze here).
- [ ] Control+left-click presents the destination menu (menu(for:) path), and plain
      right-click still does; neither double-fires.
- [ ] Draw stroke starts at the exact mouse-down pixel (recovered origin), the map holds
      fully still under a stroke (pan, rotate, and pitch all suppressed), and all three
      return when draw mode exits; the pencil button exits draw mode (Esc intentionally
      does not — accepted); WASD/arrows still steer with joystick
      active (keyboard focus survived the MKMapView swap).
- [ ] Dot does not jump on a selection/color flip while stationary.
- [ ] zh-Hant: marker labels (起點/停靠點/終點/目的地 equivalents) render localized.
- [ ] Signpost sanity in Instruments (subsystem com.harry.trailmate, category MapPerf): a
      coordinate tick shows an annotation move with NO overlay reconciliation; camera
      commands are coalesced well below 10 Hz while following.
- [ ] 705203 residual: idle CPU with the dot present vs absent (epic 037 open question).

Console / stability
- [ ] No `AttributeGraph: cycle detected` at idle or during playback.
- [ ] No regressions in the existing unit + UI test suites.
      (Known flake, pre-existing: `nonPlayingSnapshotThrottleDoesNotThrottleDeviceEmits` —
      a 120 ms timing window that can miss under full-suite CPU load; passed 3/3 isolated.
      Candidate for epic 033's test refresh.)
